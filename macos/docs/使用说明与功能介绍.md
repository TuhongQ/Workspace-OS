# Workspace OS 2.0 使用说明与功能介绍

> 版本：2.0.0 · 面向 Windows 的本地优先工作资料管理系统

## 先说结论

现在可以开始使用。首个可用版本已经完成隔离试运行：快照、索引、搜索、证据链和恢复抽样均通过；当前没有 ERROR/CRITICAL。NAS 探测、异地加密备份和管理员加密证据仍可能显示为 warning，它们不影响本机使用，但会影响完整的 3-2-1 恢复评级。

新电脑需要先在控制中心右下角点击“NAS 设置”，填入实际共享路径；本机可直接填 `\\192.168.100.110\Workspace`，无需依赖固定的 `W:` 盘符。设置保存在当前 Windows 用户配置中，不会写入或打包账号、密码。

## 最简单的打开方式：图形控制中心

直接双击工作区根目录的 `WorkspaceOS.cmd`。在窗口中选择 `D:\Workspace`，然后按按钮操作即可：初始化、收件箱整理、建立搜索、创建快照、健康检查、安全审计、查看告警和恢复准备度。窗口底部会显示执行结果；带“预览”的操作不会移动或覆盖资料。

## 1. 第一次启动

建议先用隔离试运行，不会改动正式资料：

```powershell
cd 'D:\CodeX\Workspace OS 2.0'
.\TRY-WORKSPACE-OS.cmd
```

也可以显式指定试运行目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\windows\Start-WorkspaceOSTrial.ps1" -TrialRoot "$env:LOCALAPPDATA\WorkspaceOS-Trial" -NoOpen
```

试运行通过后，再初始化正式根目录：

```powershell
python scripts/python/workspace_cli.py init --path 'D:\Workspace'
python scripts/python/workspace_cli.py new work '我的第一个项目' --workspace 'D:\Workspace'
```

常用目录：

| 目录 | 用途 |
|---|---|
| `00_Inbox` | 新文件临时入口 |
| `01_Projects` | 正在推进的项目 |
| `02_Knowledge` | 可复用知识与 Obsidian |
| `03_Areas` | 长期负责领域 |
| `04_Resources` | 参考资料 |
| `05_Archives` | 归档内容 |
| `06_Release` | 发布包、快照和恢复包 |
| `08_Indexes` | 搜索库、位置索引和报告 |
| `09_System` | 配置、证据和运行状态 |

## 2. 日常工作流

### 收件箱归档

先预览分类，不满意时不会移动任何文件：

```powershell
python scripts/python/workspace_cli.py scan-inbox --workspace 'D:\Workspace'
```

确认报告后再应用：

```powershell
python scripts/python/workspace_cli.py scan-inbox --workspace 'D:\Workspace' --apply
```

### 新建项目

```powershell
python scripts/python/workspace_cli.py new --workspace 'D:\Workspace' --name '客户交付' --template project
```

模板会创建项目说明、任务、会议记录和交付物目录。项目完成后移动到 `05_Archives`，不要直接删除。

### 搜索

先维护索引（首次或大量变更后执行）：

```powershell
python scripts/python/workspace_cli.py search-maintain --workspace 'D:\Workspace' --database 'D:\Workspace\08_Indexes\workspace-search.db' --content --output 'D:\Workspace\08_Indexes\search-maintain.json'
```

查询关键词：

```powershell
python scripts/python/workspace_cli.py search '客户交付' --database 'D:\Workspace\08_Indexes\workspace-search.db' --limit 20
```

`--project`、`--category`、`--extension`、`--status` 可继续缩小范围。索引保存内容哈希，文件内容变化后会重新识别。

### 位置索引 / NEXUS

```powershell
python scripts/python/workspace_cli.py locations --computer 'D:\Workspace' --nas 'W:\' --output 'D:\Workspace\08_Indexes\file-locations.html'
```

打开生成的 `file-locations.html` 查看电脑盘、NAS 缓存位置和文件状态。NAS 暂时不可达时使用最近一次缓存，不会因网络超时阻塞本地工作。

如果要同步差异文件，请从控制中心的“打开网页版”进入 NEXUS：勾选“仅电脑”或“仅 NAS”的文件，然后点击“同步到 NAS”或“下载到电脑”。任务会后台复制、显示进度、校验内容并刷新差异；不会删除或覆盖已有文件，冲突文件必须人工处理。

## 3. 备份、快照与恢复

生成快照前先预览：

```powershell
python scripts/python/workspace_cli.py snapshot --workspace 'D:\Workspace' --destination 'D:\WorkspaceSnapshots' --exclude-rebuildable-cache
```

确认后添加 `--apply`。快照完成后验证：

```powershell
python scripts/python/workspace_cli.py verify-snapshot 'D:\WorkspaceSnapshots\<快照目录>'
```

恢复必须先恢复到临时目录，验证无误后再人工替换：

```powershell
python scripts/python/workspace_cli.py restore 'D:\WorkspaceSnapshots\<快照目录>' --destination 'D:\WorkspaceRestoreTests\ManualRestore' --apply
```

检查整体恢复准备度：

```powershell
python scripts/python/workspace_cli.py recovery-readiness --workspace 'D:\Workspace' --snapshots 'D:\WorkspaceSnapshots' --output 'D:\Workspace\08_Indexes\recovery-readiness.json'
```

原则：至少保留多个可验证副本；不要把唯一副本放在源目录同一卷；恢复演练要记录结果。

## 4. 跨设备使用

为笔记本、台式机或移动盘生成设备清单：

```powershell
python scripts/python/workspace_cli.py device-manifest --workspace 'D:\Workspace' --device-id laptop-01 --output 'D:\Workspace\08_Indexes\device-laptop-01.json'
```

设备清单描述应同步哪些范围，不等于盲目复制全部文件。跨设备迁移优先使用已验证的发布包或快照，避免直接覆盖源目录。

## 5. 安全与健康检查

```powershell
python scripts/python/workspace_cli.py doctor --workspace 'D:\Workspace'
python scripts/python/workspace_cli.py security-audit --workspace 'D:\Workspace'
python scripts/python/workspace_cli.py alerts --workspace 'D:\Workspace'
python scripts/python/workspace_cli.py evidence-verify --workspace 'D:\Workspace' --verify-current --output 'D:\Workspace\08_Indexes\evidence-verify.json'
```

重点看：是否有 ERROR/CRITICAL、最近快照是否可验证、证据链是否连续、NAS/异地备份是否过期。warning 表示能力或外部条件不足，不等于本地文件损坏。

## 6. 推荐的 5 分钟习惯

1. 新文件先放 `00_Inbox`。
2. 每天运行一次 `scan-inbox` 预览并确认归档。
3. 项目阶段性完成后运行索引维护。
4. 重要节点生成快照并执行验证。
5. 每周查看 `alerts` 与 `recovery-readiness`。

## 7. 不要这样做

- 不要直接删除未知来源文件；先归档或移入回收站。
- 不要在快照、恢复或扫描过程中强行断电/拔盘。
- 不要把 `09_System`、索引数据库或证据文件当作普通资料改名、移动或清理。
- 不要把 NAS 不可达时的缓存位置误认为实时 NAS 状态。
- 不要把恢复测试目录当成正式源目录。

## 8. 常见情况

| 现象 | 处理 |
|---|---|
| 页面看起来没有变化 | 重新运行 `locations`，再刷新 `file-locations.html` |
| 搜索结果不全 | 先运行 `search-maintain --content` |
| NAS warning | 检查盘符/网络；本地功能可继续使用 |
| 恢复评级不是满分 | 通常是缺少异地加密副本或独立介质 |
| 出现 ERROR/CRITICAL | 先停止清理操作，保存 `alerts` 报告，再按报告指向处理 |
